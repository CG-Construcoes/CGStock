Documentação da API

1. Visão geral

A qweb-api é um serviço Node.js + TypeScript (Fastify) que roda na rede interna e cumpre dois papéis:

  1. Compatibilidade QWeb — replica o contrato da API legada Kiweb (wminformaconcgi) lendo direto do SQL Server da Informakon, em modo somente leitura.
  2. Sincronização — copia os dados de suprimento/almoxarifado do Informakon para o PostgreSQL do CGStok, de forma incremental e idempotente. O Informakon é a fonte da verdade.
[SQL Server Informakon] --(SELECT)--> [qweb-api :3085] --> [PostgreSQL CGStok] --> [CGStok]
Restrições: rede interna apenas (não expor na internet). Nenhum INSERT/UPDATE/DELETE/DDL no SQL Server — todas as queries usam WITH (NOLOCK). Credenciais somente em .env.

6. Modelo de sincronização

  • Espelho (InfMirror): cópia bruta da linha fonte + sha256 em (entity, sourceKey). É a fila persistente: projectedHash = NULL = pendente de projeção (retry automático); 'DEL' = exclusão tratada; deletedAt = ausente na fonte.
  • Projeção: upsert nas tabelas do CGStok só nas linhas cujo hash mudou — idempotente, reexecutável sem duplicatas.
  • Feature flag: SystemSetting 'informakon.sync.enabled' liga/desliga a projeção (o espelho continua atualizando).
  • Status: SyncCheckpoint (último sucesso/erro por entidade) e SyncRun (histórico) alimentam "atualizado às HH:MM" no CGStok.
  • Detecção: sem rowversion no SQL Server → full-scan + hash por ciclo (cron default */2min, ciclo incremental ≈ 9 s).
  • Exclusões: soft-delete — status='INACTIVE' na projeção (estoque → quantidade 0). Nunca DELETE físico.
  • Custos: valores/preços ficam só no espelho (dado sensível).
